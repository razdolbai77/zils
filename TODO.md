# zils Implementation Plan

- [x] Scaffold the Node.js and TypeScript workspace, npm package metadata, MIT licensing metadata, lint/build/test scripts, and the `src/`, `test/`, `examples/`, and `vscode/` directory layout so the project matches the intended `merls`-style architecture.
- [x] Add initial fixture corpora for valid and invalid Z80 assembly, using the Zilog Z80 manual as the baseline reference for instructions, registers, flags, and addressing modes, and lock the supported textual syntax down with fixture-driven tests before parser work begins.
- [x] Add initial fixture corpora for valid and invalid eZ80 assembly, using the Zilog eZ80 manual as the reference for ADL-sensitive forms, 24-bit addressing, and eZ80-only instruction variants, and lock the intended opt-in dialect behavior down with tests before implementation.
- [ ] Define shared syntax and metadata modules for Z80 and eZ80 instruction sets, registers, condition codes, addressing modes, suffixes, and directives so dialect differences are centralized and test-driven.
- [ ] Implement the lexer with tests covering identifiers, labels, numbers, comments, strings if supported, punctuation, indexed operands, and token forms needed by both Z80 and eZ80 source.
- [ ] Implement expression parsing and evaluation primitives with tests covering numeric formats, unary and binary operators, parenthesized expressions, current-location references, and operand shapes required by both dialects.
- [ ] Implement line parsing with tests that classify labels, instructions, directives, data declarations, comments, blank lines, malformed input, and dialect-specific constructs without mixing Z80 defaults with eZ80 opt-in behavior.
- [ ] Implement the document model with tests that preserve line structure, token spans, parse errors, and dialect-aware semantic facts needed downstream by diagnostics and LSP features.
- [ ] Implement symbol collection with tests covering global labels, local labels if supported, equates, constants, data symbols, duplicate definitions, and dialect-aware symbol metadata.
- [ ] Implement workspace indexing and cross-file resolution with tests covering project scanning, include or source-loading directives chosen for the supported assembler syntax, cache invalidation, and stable URI normalization on Windows.
- [ ] Implement parser-based diagnostics with tests covering malformed syntax, unknown instructions, wrong operand forms, unresolved symbols, duplicate symbols, and clear separation between valid Z80 syntax and eZ80-only syntax rejected in default mode.
- [ ] Implement CLI argument parsing and server bootstrap with tests for the stdio contract, default Z80 mode, explicit `--cpu z80`, explicit `--cpu ez80`, and predictable rejection of unsupported flag combinations.
- [ ] Implement `initialize`, document sync, and diagnostics publication in the LSP server with integration tests matching the standalone-client contract expected by `coc.nvim`.
- [ ] Implement document symbols and workspace symbols with tests covering labels, equates, constants, and dialect-aware symbol categorization across open documents and indexed workspace files.
- [ ] Implement go to definition and find references with tests covering same-file and cross-file navigation, local scopes, duplicate-name edge cases, and dialect-aware symbol use sites.
- [ ] Implement hover with tests covering instructions, directives, registers, flags, symbols, and dialect-specific help text for Z80 versus eZ80 forms.
- [ ] Implement completion with tests covering opcodes, directives, registers, conditions, symbols, and context-sensitive suggestions that default to Z80 while exposing eZ80 additions only in eZ80 mode.
- [ ] Implement semantic tokens with tests covering labels, instructions, directives, registers, numbers, comments, operators, and dialect-specific tokenization differences needed for editor highlighting.
- [ ] Implement rename with tests covering safe symbol renames across files, local-scope protection, and refusal cases for ambiguous or unsupported rename targets.
- [ ] Implement formatting with tests for document, range, and on-type formatting decisions appropriate for assembly source while keeping behavior stable across both dialects.
- [ ] Implement folding ranges, document highlights, and selection ranges with tests covering common assembly source structures and nested syntax regions supported by the parser.
- [ ] Implement signature help, inlay hints, code actions, code lens, document links, and call hierarchy with tests matching the current `merls` feature surface and adapted to Z80-family assembly semantics.
- [ ] Add regression and performance coverage for large workspaces and instruction-heavy files so diagnostics, indexing, and navigation remain responsive as feature parity approaches `merls`.
- [ ] Add `examples/coc-settings.json` and any required smoke coverage so the standalone server is proven usable from `coc.nvim` with the packaged CLI contract.
